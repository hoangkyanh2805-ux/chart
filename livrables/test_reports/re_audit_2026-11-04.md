## Findings, ordered by priority

1. **P1 — Current renderer and renderer test do not parse.** TypeScript reports TS1109 at renderPaperTheme.ts:289, TS1005 at :784, and TS1005 at paperThemeRenderer.test.ts:201–202. An unfinished `const isCustomText =` is immediately followed by another declaration. Working-tree changes also mix phase-based and seconds-based sequences. This blocks compilation; fix the merged declarations/control blocks before assessing visual correctness. [1]

2. **P1 — Telegram credential is hard-coded in tracked API source.** feedback/route.ts:23 contains a literal bot credential as fallback to the environment variable. Its current validity was not tested. Remove the fallback and rotate/revoke the exposed credential through the account owner. The route sends notifications for valid submissions; the ticket unit test calls the real handler without mocking this path, so running the suite can send a real message and write a SPEC file. The whole verifier run was interrupted after this was discovered; delivery is unverified. [2][3]

3. **P1 — Feedback filename permits directory traversal.** Caller-controlled `ticketId` is interpolated into the path without normalization/allow-list checks, unlike category. A value such as `x/../../../audit-proof` produces `SPEC-x/../../../audit-proof-test.md`, which path.join resolves outside livrables/specs. If the destination is writable, submitting feedback can create/overwrite a Markdown file outside the intended directory. This was assessed statically; no exploit request or filesystem overwrite was performed. Reject separators and enforce the resolved destination beneath specs. [4]

4. **P1 — Goal verifier can report completion with dirty Git and an offline/unhealthy server.** It always appends Git PASS when status is readable, and explicitly appends `PASS (Offline / Dev)` on connection errors. HTTP warning/timeout paths do not set allPassed=false. Consequently test success alone can lead to GOAL COMPLETE without satisfying the documented runtime/Git gate. Fail the gate on these conditions or explicitly revise the contract. [5][6]

5. **P1 — Mutation success is simulated, not measured.** test:mutation sleeps and prints success; it never mutates production code or invokes a test command. The coordinate test embeds broken helper functions and expects their broken behavior to be true, which does not show that the production test suite kills mutants. The third helper tests random jitter, not dropped export frames. The runner returned success even while TypeScript found syntax errors. Implement isolated mutants and verify failing test exit codes. [7][8]

6. **P1 — Export compliance gate can use an obsolete validation result.** ExportModal reuses validationReport whenever present; setters for candles and execution do not invalidate it. A valid setup can be audited, then changed, and exported with the old approval. Validate the exact export snapshot inside the export handler and abort on failure. Static control-flow finding; browser reproduction not performed. [9][10]

7. **P1 — Recorder failures can leave export locked.** The modal sets isExporting before calling the recorder. captureStream/start and the fallback constructor can throw; recorder.ts never calls options.onError and has no recorder.onerror handler. The recovery callback provided by the modal therefore does not receive these errors. Centralize error/finalization and release streams/timers. [11][12]

8. **P2 — Export does not include narration or fixed production resolution.** The recorder receives only canvas.captureStream; narration preview plays a separate Audio instance. Canvas backing dimensions are taken from the preview rectangle times devicePixelRatio, with variable-width landscape styling. Thus voiced preview does not imply voiced output, and selecting a format does not guarantee 1080p pixels or landscape ratio. Export from a dedicated fixed-size render target and mux synchronized audio. [13][14][15]

9. **P2 — Frame timing is wall-clock based, not deterministic encoding.** A chained setTimeout drives render updates while MediaRecorder runs independently; there is a further 200 ms stop delay. Slow rendering or background throttling can stretch output and alter cadence. Actual frame loss was not measured. Use timestamped encoding and validate frame counts/duration on a produced artifact. [16]
